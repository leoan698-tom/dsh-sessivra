# @会话：上下文引用与通信

功能基线 0.3.0-dev.15，当前分发 0.3.0-dev.16，宿主 DSH 0.2.1-rc.5。

在输入框使用宿主原生 `@` 选择会话。候选和选中标签不再添加“发送至/发送给”，插件不再另外展示发送专属列表。文件和目录引用保留。

- `@会话B 根据它的结论，整理下一步计划。`：给当前会话引入 B 的上下文，不向 B 发消息。
- `@会话B 把这个检查任务交给它，完成后回复我。`：AI 解析用户通信意图，绑定 B 的准确 ID，再发送并接收关联回复。
- `@会话B @会话C 对比两边的结论，把待修复事项发给 B。`：两份上下文均可用，发送明确绑定 B，不默认发给最后选中的 C。

可引用普通会话、团队队员、团队外和多级子智能体、一次性执行历史。宿主目前每条消息最多引用 3 个会话；上下文是受预算限制的历史快照，可能截断，不能当作完整共享历史或实时同步。快照中的内容是资料，不能自行授权通信或执行工具。

普通会话通信和当前主会话向自己直接拥有的可继续子智能体派任务继续支持。一次性对象只读；其他主会话拥有的子智能体及更深下级可以引用，但不会因此获得越级派任务权限。Team 任务板仍由团队工具维护。

仅选择、引用或查询目标不会授予新通信许可，不唤醒目标。实际发送需要当前用户明确要求。消息工具提供准确引用对象与可发送状态，随后复核归属、工作目录、现有拒收设置、消息时效和去重。queue/insert 仍由 AI 按用户要求选择。

旧版草稿中的会话芯片会在提交/复制时转换为原生引用；历史消息文本保留。已安装数据无新增 schema 字段，可按正常退出后通过官方 CLI 回退 dev.14；更早版本限制见 [安装与回退](OPERATIONS.md)。

安装命令见 [操作说明](OPERATIONS.md)，验证边界见 [测试报告](TEST_REPORT.md)，发布包哈希见 GitHub Release 的 SHA256SUMS.txt。

# 会话树使用普通会话的父子关系

2026-11-01 补充：用户要求智能体团队成员也在会话列表按主子树展示。[ADR-0006](0006-team-members-in-session-tree.md) 扩展本决策的展示范围；本决策对普通子会话创建、身份和通信的约束继续有效。

2026-10-30，用户明确纠正：主子树按会话组织，不能按 subagent 归属组织。此前 0.3.0-dev.1/dev.2 将创建子会话解释为创建 subagent，并将其子执行器混入列表，属于实现错误，不能作为目标通过证据。

树节点必须是可独立打开、继续聊天、被 `@` 选择和接收普通消息的会话。新建子会话通过正式 Session Controller 创建普通会话；插件按准确会话 ID 保存显式父子关系。既有普通会话分支可以读取宿主的普通 parentSession 关系。subagent、子执行器、委派深度大于零的执行上下文不作为会话树节点，也不作为此创建功能的产物。

关系存放于独立 conversations domain，随 profile 重开恢复。普通会话继续使用同一套排队/插入与关联回复通信，不使用 subagent 专属路由或内部 Host 协议。不能从一次普通 `@` 通信推断或改写会话归属。

侧栏使用紧凑导航行、独立展开箭头和单行标题；完整标题可在键盘聚焦时查看，工作目录完整路径保留于辅助信息。此前粗糙列表截图是失败证据，修复后须核对实际安装界面。

## 子会话推理等级

创建工具应接收用户指定的 reasoningEffort，在子会话首个请求前应用并保存会话局部意图，不改父会话或全局默认。rc.5 的 sessionController.selectModel 同时保存全局默认，因此不用它实现局部设置；采用公开的 Agent-scoped agent/request 扩展和 model/selection 会话事件。首个请求落盘后由宿主正常会话选择管理后续请求，不永久覆盖用户选择。

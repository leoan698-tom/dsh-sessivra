# 以会话协作体验作为交付目标

2026-10-30，用户重新明确目标：从 `@` 选择某个 workspace 下的会话并向其发送内容，可选择排队等待接收会话完成当前任务，或直接插入；也可按要求创建子会话，并在会话列表中以树展示主子关系。对标用户描述的 Claude 会话通信与主子会话列表体验。反复点击配对许可不属于目标体验。

本决策扩展 [ADR-0002](0002-pure-plugin-communication-and-dispatch.md) 的产品范围，取代“独立根会话通信即可代表完整目标”的解释。子会话创建与会话树纳入目标；业务产出自动验收和失败自动恢复仍不因本次确认自动纳入。保留纯插件边界，先验证正式宿主接口；发现接口缺口时记录具体缺口，不修改安装包，也不擅自将树形展示降为可豁免项。

## 2026-10-30 后续交互修订（优先于下文初始调查快照）

发送方式由 AI 按每条消息决定，用户只需 `@` 选择会话并用自然语言说明要求。删除“此会话 → 目标 / 尚未发送 / 发送方式 / 清除”整条底栏，不以其他控制栏替代。新任务、等待或时机不明默认 queue；即时调整当前执行用 insert；明确的用户时机要求优先。沿用宿主 followup(next-turn) 与 steer(next-step) 正式接口，insert 不取消执行中的工具。历史发送方式偏好不影响新消息。普通子会话关系仍依据 ADR-0004。

## 确认的交互与验收目标

| 能力 | 应有行为 | 当前源码核对结果 |
| --- | --- | --- |
| `@` 选会话 | 能按 workspace 识别、查找并选择准确会话；用户明确选择目标后发送内容 | 有 `@` 下的发送入口，但搜索转入 `@>`；完整 workspace 导航体验待适配 |
| 排队发送 | 接收会话忙时保留消息，等当前执行结束后自动按队列发送；可观察排队状态 | 未实现可选的忙时等待调度；现有 hold/release 不能作为通过证据 |
| 直接插入 | 用户可明确选择向运行中的接收会话插入内容，并看到实际接收结果 | 当前 busy 自动使用 steer，缺少用户选择模式 |
| 创建子会话 | 根据用户要求创建真实子会话，保存正确的父子关系与 workspace | 当前插件未实现，且显式排除 subagent/delegationDepth 目标 |
| 会话树 | 在会话列表中展示主子层级，可打开对应会话；关系重开后仍可恢复 | 当前插件未实现；正式接口支持程度待验证 |
| 连续使用 | 选择目标、选择发送方式、发送；正常发消息和切换目标不反复要求配对许可 | 当前切换目标或清除选择会撤销已有配对许可，与目标不符 |

“当前任务完成”在排队调度中先以宿主当前执行结束、能够接收下一条任务为操作性定义；这不等于插件判断业务产出合格。实际可用的执行结束信号及队列恢复语义需要通过宿主接口验证。

用户在界面明确选择收件目标并发送，表达该次通信意图；后台模型不得因此获得任意改写目标或扩大通信范围的能力。新版应消除正常通信链路上的重复配对点击，同时保留准确目标绑定、用户撤销和宿主原有工具权限。具体授权实现仍待设计，不将本文当成已迁移现有许可或已授予全部会话全局权限。

## 证据与执行顺序

保留既有合成、真实模型、费用与失败证据。它们证明各自候选和场景的通信能力，不能证明新增的排队、子会话或树已经交付。暂停沿旧范围继续付费验收，待新实现范围及用例明确后再安排。暂停执行不代表已经修改运行中的费用支撑状态。

下一步先核对正式 SDK 的会话创建、父子关系、执行状态及会话列表扩展接口，形成可实现路径与具体缺口；随后适配 `@` 选目标、连续发送及排队/插入模式，再接入子会话与列表树。先做免费验证，再按最终冻结候选修订完整验收。官方 Flash、累计10元及既有累计账本继续作为付费边界，不重置已发生费用。

本地 SDK 已见 AgentRegistry.create、parentAgent 与 parentSession 等能力声明，只能作为接口调查线索，不能据此宣称现装宿主支持完整子会话树。

# 以纯插件交付跨会话通信与调度

2026-10-30 范围更新：用户明确要求可选排队/插入、按需创建子会话和会话列表树，并纠正重复配对许可的交互。当前产品范围以 [ADR-0003](0003-session-collaboration-product-scope.md) 为准；本文保留此前决策的历史依据，纯插件边界继续适用。

2026-10-28（America/Los_Angeles），用户确认当前项目优先交付同一 Host、同一 profile 内的跨会话通信与调度：在 A 主输入框选择 B，按明确许可发送任务或方向调整，查看消息状态并接收关联回复。任务完成判定、产出自动验收、失败自动恢复和持续追踪属于另一阶段的任务闭环管理，当前不纳入项目交付范围。

项目保持纯插件边界，通过正式宿主接口集成。宿主改动及其兼容维护不纳入本仓库；沿用 [ADR-0001](0001-delivery-reference-stays-distinct.md)，保持投递引用与只读引用分开，已提交气泡的可读显示由宿主支持。

## 取舍与后果

将宿主改动纳入项目可以直接处理气泡显示，但会扩大版本兼容与维护责任；将通信扩展为任务闭环管理还需要独立的任务及验收模型。当前先把通信与调度做好，接受气泡显示依赖宿主的限制。

插件可继续完成重开、跨工作目录和冷会话的验收。消息投递或关联回复的状态不证明业务任务完成；合成流程通过也不等于真实业务验收。

同日用户进一步确认：合成原生 N1–N8 全部通过后，还须通过受控的真实模型验证，插件才可单独阶段交付。宿主气泡显示缺口继续保留并单列，不阻止满足标准后的插件阶段交付；整体体验仍待宿主支持。当前验收标准及待确认方案见 [插件阶段交付标准](../ACCEPTANCE_CRITERIA.md)。此次确认未新增验收结果。

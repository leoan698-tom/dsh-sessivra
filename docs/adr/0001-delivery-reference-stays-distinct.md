# 投递引用不并入只读引用

已提交的用户气泡会把投递引用显示成原始文本，因为现装宿主只把只读引用投影成可读标记。本候选保持两种引用分开，不把投递目标改写成只读引用，也不改选择契约来绕过气泡。气泡显示留给认识投递引用的宿主；本仓库不修改已安装的宿主包。

## 考虑过的做法

- 改用只读引用，让现有气泡直接画出芯片。这会把“给当前会话一份低信任快照”和“把文本发给目标会话”变成同一种标记。
- 插件提交可读文字，另用一条绑定保存精确目标。这会换掉当前选择契约，已经收集的合成技术证据不能沿用。

## 后果

产品目标里“气泡不再把内部引用当正文”这一半，要等宿主投影。当前契约上的重开、跨工作目录和冷会话验收仍可继续。

2026-10-28 用户确认插件可单独阶段交付，宿主气泡显示缺口继续单列；此处的整体体验依赖不阻止达到标准后的插件阶段交付。具体标准见 [插件阶段交付标准](../ACCEPTANCE_CRITERIA.md)，范围决策见 [ADR-0002](0002-pure-plugin-communication-and-dispatch.md)。两类引用继续保持分开。

# 智能体团队成员在会话列表中按主子树展示

后续决策：dev.13 依据用户追加要求，通过 [ADR-0007](0007-parent-child-messenger-transport.md) 扩展 `@` 与主会话对子智能体通信。下文关于不进入 Messenger 候选的文字仅描述 dev.11/dev.12 的历史范围。

dev.14 依据用户「新建智能体应自动入树，避免漏显示」，通过 [ADR-0008](0008-automatic-subagent-tree-discovery.md) 扩展多级、一次性和创建/外部执行状态节点的自动发现。下文对展示类型的限制同样保留为历史。

2026-11-01，用户要求「将主会话中智能体团队中的成员，也采用主子树的结构在会话列表中展示」。这扩展 ADR-0004 的导航展示范围，不改变既有普通子会话的创建与通信语义。

同一工作区的普通会话树增加团队成员节点。使用宿主 Session Controller 的会话列表与公开 agentTeam/subagent 投影，核对名册 role=teammate、phase=active、准确成员 ID、子会话 origin=subagent、直接 parentSessionId 和 continuable 描述符。父会话或成员已归档、成员创建未完成或失败、关系不一致、未加入团队的 subagent 均不作为团队成员节点显示。不从名称或任务文本推断关系，也不写入插件 conversations 父子关系存储。

节点显示团队成员名称、「队员」标识和运行状态；完整会话标题或职责说明用于悬停提示。点击通过正式 UiWorkspace.openSession 的 {parentSessionId, childSessionId, mode:'continuable'} 地址打开，让宿主拥有子智能体历史、输入、恢复和生命周期。

会话列表缺少冷会话投影提示时，使用 SessionQuery.observeSession 获取一次可释放只读观察。查询不 resolveAgent、不创建或唤醒 Agent、不发送消息；宿主可能准备/回放日志，返回客户端的内容只包含导航所需字段。

普通 @ 收件候选继续排除所有 subagent。session_create_child 仍创建普通会话，session_message_* 与 session_progress 不获得团队成员权限。Team 的名册、共享任务、队员身份及原始历史均由宿主管理。仅查看、搜索或打开树节点不启动模型请求。

dev.11 验收覆盖真实父子地址、未加入团队/失败成员/归档过滤、普通会话回归、冷列表恢复、查看无模型调用，以及主会话实际 8 名队员的桌面展开与导航。

## 同日追加：团队外子智能体

用户随后要求「另外两个团队外的子智能体也放到主会话主会话下面，用不同标识与团队队员区分，同样支持点击打开」。dev.12 将导航范围扩展为直接归属于普通主会话的 continuable 子智能体，包含团队名册外的对象。使用持久描述符中的任务名称，显示「子智能体」标识；团队成员继续使用名册名称和「队员」标识。两类均通过原生父子地址打开。

失败/创建中的名册成员不以团队外子智能体身份重新出现；归档、没有可见父会话、描述符缺失或非 continuable 的对象仍不显示。没有 Team 名册的主会话也可展示符合条件的团队外子智能体。团队投影存在失败时不推断名册外身份。普通 @ 候选、消息权限、团队任务与存储边界沿用上文。

本轮桌面核对了两个既有团队外子智能体均可打开，同时保留 8 名队员的展示和原始归属。
